#### 用量历史 · 模型上下文窗口 · 桌面打包验证

- **协议加性方法 `provider/usageHistory`**（`agentj-protocol` + `agentj-ipc` + `agentj-cli` +
  `@agentj/sdk`）：第 **29** 个方法（schemas **81**，协议版本 **0.20.0**），读内核**落盘**的用量
  取样——`ProviderUsageHistoryParams { provider?, kind?, since?, limit? }` →
  `ProviderUsageHistoryResult { provider, retention_days, samples: [{ at, windows }] }`。
  `retention_days` 回报本次**实际生效**的保留期（客户端据此标注横轴），`samples` 按 `at` 升序，
  `limit` 上限 `5000` 且只保留最新的一端；查询是纯本地读，不触网、不需要凭据。
- **取样只在真取数时发生**（`agentj-cli::usage_history` + `CliProviderService`）：只有上游真的
  答出窗口才追加一条样本——300s 缓存命中、`stale: true` 的回落数据、`no_credential` / 鉴权失败 /
  网络不可达一律不写（否则趋势画的是「客户端行为」而不是「用量」）。存储为**每个 provider 一个
  文件**（`<provider>.json`，`version: 1`，provider 名须是 `[a-z0-9._-]` 的 ≤64 字符安全名），
  目录按 `[web] state_dir` → `$XDG_DATA_HOME/agentj/usage` → `$HOME/.local/share/agentj/usage`
  解析，目录 `0700` / 文件 `0600` / `*.json.tmp` + rename 原子替换；写入前先做**重复折叠**（60s 内
  且窗口值完全没变 → 不落新样本），再按保留期与条数上限裁剪。任何 IO 失败只 `warn`，绝不让
  「记历史」失败拖垮触发它的那次 `provider/usage`。

#### token 预算接缝 · 三平台打包 · attach 审批 · grep 时限

- **可插拔 `TokenCounter` + 分类校准**（`agentj-core::budget`）：新增
  `pub trait TokenCounter { fn count_text(&self, text: &str) -> usize; }` 与默认实现
  `HeuristicTokenizer`，把 token 估算收敛到**一个接缝**（真词表只需换实现，裁剪逻辑不动）。
  `HeuristicTokenizer` 按**字符类**计费：ASCII 字母/空白 4 chars/token、ASCII 标点 2.5、
  CJK（Han/Hiragana/Katakana/Hangul/兼容表意）1.25、其余 BMP 1、星平面 0.5；
  每一类都**不低于**旧启发式（ASCII/4 + 非 ASCII×1），因此不会把预算算小。
  `estimate_tokens` 签名与语义保持不变，旁路新增 `message_tokens_with` / `request_tokens_with`。
- **工具定义占用预算**（`agentj-core::budget` + `ContextPipeline::fit_with_tools` + turn runner）：
  工具定义**永不**被裁剪器丢弃，但它确实占窗口，所以现在先按
  `definitions_tokens(defs) = Σ(name + description + input_schema + 12)` 预留，
  再让历史去抢剩下的预算。`ContextPipeline` 新增默认方法
  `fit_with_tools(messages, defs, budget)`，自定义 pipeline 无需改动即获得新语义；
  `TurnRunner` 组装请求改走它。core 的 `DefaultContextPipeline` 覆写该方法，把定义开销记在
  **总量**上（`fit_messages_with`）——否则 `fit` 自己的 1k 下限会把总量重新顶回去，小窗口 + 大
  工具表必然超限，且超限重试发出的请求逐字节相同。
- **工具调用收缩器按 token 计量**（`agentj-core::budget`）：收缩器此前用字符数判断
  （`cap × 4` 字符），与估算侧各写一份换算率，而且一个「字符/token」常数根本盖不住字符类差异——
  密标点 JSON 是 2.5 chars/token、CJK 是 1.25、ASCII 词是 4。现在直接拿同一个 counter 计费：
  `estimate_tokens(payload) > cap` 才替换成标记，超预算的 payload 不再因「字符数看着不多」而放行。
- **owner 断连只结算真正的孤儿会话**（`agentj-ipc`）：`settle_owner_pending` 先取「该连接拥有的
  会话」快照再 `clear_owner`，两者之间另一客户端可能已 `session/run` 认领同一会话——旧实现照样
  `cancel_session`，把**新 owner 刚提出的**审批按 `disconnected` 拒掉。现在快照落盘后重新判定归属，
  只结算仍然无人认领的会话（`disconnect_does_not_settle_a_session_reclaimed_meanwhile`）。
- **只有首条 system 提示免于裁剪**（`agentj-core::budget`）：此前 `truncate` 对所有 `system` 角色
  早退，而裁剪器又无条件保留最新一条——一条被注入在会话中段、且恰好是最新的 `system` 消息因此既不
  裁剪也丢不掉，请求可以越过预算（超限重试再发逐字节相同的请求）。现在豁免条件收窄为「首条 + system」。
- **`run --attach` 报告并拒绝远端审批**（`agentj-cli`）：attach 收到 `$/permissionRequest` 时打印
  `warning: run --attach cannot answer approvals; denying <tool> (<request_id>) — …` 并主动回一条
  `permission/respond` **deny**（JSON 由 `serde_json` 序列化，不手拼）。被拒的 deny
  （已结算 / 归属不符 / 重复 id）只打印 `warning: attach deny was refused: …` 并继续读流——
  以前任何 `error` 帧都会让 attach 以非零退出，看起来像 run 本身失败。此前 attach 既不答复也
  不报警，只能等远端 `[permission] timeout_ms` 到期；现在非交互客户端会如实说出「我拒绝了这个
  审批请求」，而不是装死。审批归属语义不变：`--attach` 的审批归远端内核的订阅客户端。
- **macOS `dmg` / Windows `msi` 打包作业**（`.github/workflows/ci.yml`）：
  `desktop-package-macos`（`macos-latest`，`--bundles dmg`，`check-artifacts.sh macos`，

  不公证**（用户绕过见 [`docs/guide/desktop.md`](../guide/desktop.md)）。
- **仓库不变量 `desktop-package-platforms`**（`scripts/tests/assert-ci.sh`，ci check 9 → 10，

#### 可观测性 · 配置校验 · 协议截断上报 · 用量面板（协议 0.21.0）

- **限流快照落盘不再丢更新**（`agentj-ipc`）：`persist` 的 5s debounce 写盘先取 `dirty` 快照再

### Fixed

- **`grep` 进程内回退没有时间上限**（`agentj-tools`）：无 `rg` 时的 `search_native` 只有 2000 条
  命中上限，在超大树上可能长时间不退（`rg` 子进程那条路径有 executor 的进程组超时，回退路径没有）。
  现在 `search_native` 与 `scan_entry` 都持 `Instant::now() + timeout` 期限，超期即
  `Err(ToolError::Timeout(timeout))`——与 `bash` / `rg` 一致的结构化超时，不再把「跑不完」伪装成
  一次成功的部分结果。`rg` 缺失时调用方已钳制的 deadline 是唯一预算。入口与每个 entry（含
  `fs::read` **之前**）都检查期限：预算已经花光时，即使根目录不可遍历也不会返回「无命中」，
  文件内部的 512 行粒度检查负责单个超大文件。
- **空的 `[web] state_dir` 被当成有效路径**（`agentj-cli`）：`state_dir = ""` 解析出
  `PathBuf::from("")`（实际指向进程 CWD）并赢得解析链，于是每次 metrics 落盘都失败并刷
  `cannot persist login metrics state ...`。现在空串按**未设置**处理，回落到
  `$XDG_DATA_HOME/agentj` → `$HOME/.local/share/agentj`，两者皆无时返回 `None` 并复用
  「无状态目录」启动警告。
- **`permission/respond` 不再是单一赢家**（`agentj-permission`）：`respond` 原先在两次独立加锁之间
  先看 `_keepalive` 再 `send`，于是两个并发 `respond` 都能通过检查（双双「成功」），`respond` 与
  `cancel_session` 竞争时用户的 Allow 还可能被断线 Deny 覆盖。现在 `PendingRequest` 带一次性
  `finished: Arc<AtomicBool>`，`respond` / `cancel_session` / `clear_all` 一律先 `swap(true, AcqRel)`
  再投递——恰好一个结算者生效；`respond` 还会先解析所属会话再取认领，避免「认领被烧掉但决定没送出」
  导致工具白等 `[permission] timeout_ms`。
- **符号链接可绕过工具路径校验**（`agentj-permission` + `agentj-core` + `agentj-ipc`）：
  `engine::eval_path` 原先纯词法归一化 + 前缀比对，指向工作区外的符号链接被当成「工作区内」→
  现改为 fail-closed 的 canonicalize 判定（根目录不可解析时退回词法，目标不存在时取最近存在祖先
  判前缀），`link → /` 作为工具路径一律 Deny。
- **不存在的写入目标被误判为逃逸**（`agentj-permission` + `agentj-ipc`）：`write src/new/deep.rs`
  这类目标不存在但合法落在工作区内的路径，过去因 `canonicalize` 失败直接 Deny / 报 `OutsideRoot`；
  现在按最近存在祖先 + 剩余词法尾部判定（`dir/file.rs` 之类不存在的新文件 = `Ask`）。
- **工具参数被重定基到工作区外**（`agentj-core::tool_paths`）：`rebase_tool_args` 过去对逃逸路径也
  做词法归一，模型给的绝对外部路径会被改写成「根 + ../../…」的怪路径；现在 `Outside` 一律原样返回，
  由权限系统裁决。
- **`OutsideRoot` 文案误诊 EACCES**（`agentj-ipc::file_list`）：祖先目录不可读（EACCES）过去报
  「逃逸出根」，现文案覆盖「不可解析或超出根」两种情形（仅文案，wire 字段不变）。

  `tracing::error!` 记录（含请求 id）。
- **符号链接叠加 `..` 仍可越界**（`agentj-core::paths`）：`resolve_within_root` 原先先做 `..` 词法折叠再

  `spawn_tcp_signal_task` 把 `tokio::signal::unix::signal(...)` 写在 `tokio::spawn` 的 async 块内，
  而 tokio 只在 `signal()` **首次被调用**时安装进程级 OS 处理器、`tokio::spawn` 又是惰性的——在任务
  首次被 poll 之前到达的 SIGTERM 仍按默认处置杀死进程（以信号 15 退出、不走优雅关闭链），在

  `execute_with_timeout` 的「超时返回、子进程继续跑」语义并不能真正止损。现在两者统一经
