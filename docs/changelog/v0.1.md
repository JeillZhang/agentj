# v0.1.x —— 全部特性

> 发布：0.1.0（2026-10-18，功能）
> 协议：`PROTOCOL_VERSION` **0.19.0**（28 方法 / 78 schemas / 18 crates）

本文档是 **`0.1.0` 的完整特性清单**：项目全部能力合并于 `0.1.0` 一个版本，不再按历史小版本
拆分。用户可见特性见 [`docs/guide/`](../guide/)，协议契约见
[`docs/specs/ipc-protocol.md`](../specs/ipc-protocol.md)。

## 0.1.0 —— 内核 + 全端（功能）

### Added

#### 内核与协议

- **IPC 协议契约**（`agentj-protocol`）：JSON-RPC 2.0 信封 + 错误码 + 28 方法 params/result +
  流式/订阅/权限/提问/文件列举/订阅服务类型；78 JSON Schema（schemars 生成 + 漂移门禁）+
  方法注册表 `protocol/methods.json` + 跨语言类型绑定 `@agentj/protocol`；人类可读规范
  `docs/specs/ipc-protocol.md`。协议版本 **0.19.0**。
- **内核**（`agentj-core`）：Kernel 混合总线 + 模块 trait 注册表 + ServiceRegistry（同步/异步）
  + TurnRunner 总线化 turn 编排；EventBus 订阅/发布 + 重入防护（`EventGuard` thread_local /
  `MAX_EVENT_DEPTH=16`）。
- **Agent 循环（流式）**：`AgentLoopModule` + `ToolExecutorModule` + `SubAgentService`。
- **token 预算**（`budget`）：请求前 `estimate_tokens` 估算 + `fit_messages` 裁剪 + 上游超限
  `retry_budget` 收紧重试（`ContextPipeline::fit` 默认接入）。
- **文本工具调用还原**（`text_tool_call`）：把模型写成纯文本方言的工具调用无歧义还原为真实调用；
  无法还原时纠偏重发并如实报错，不把标记当结论。
- **TurnArtifact**：FileChange / Todo 产出 + 自研 unified diff（per-run `run_id` / `seq`）。
- **ToolCallContext**：会话根上下文，工具相对路径重定基。

#### 内置工具与扩展

- **内置工具**（`agentj-tools`）：`bash` / `glob` / `grep` / `read` / `write` / `todo`（共 6 个）；
  `grep` 优先 `rg`、缺失时回退进程内检索（`regex` + `globset` + `walkdir`）。
- **MCP**（`agentj-mcp`）：子进程 MCP 客户端 + `McpConnectionManager` 长驻连接。
- **上下文管线**（`agentj-context`）、**用量统计**（`agentj-stats`）、
  **Skills 加载器**（`agentj-skills`）。
- **插件系统**（`agentj-plugin`）：manifest + 状态机 + 依赖图 + libloading。
- **License**（`agentj-license`）：Ed25519 许可证校验（entitlements + free mode）。

#### 模型提供方

- **三线 wire-format + Mock + Ollama**（`agentj-model`）：OpenAI-compatible SSE /
  OpenAI Responses / Anthropic Messages / opencode-go / Ollama / Mock。
- **opencode-go 订阅**：`agentj auth` 凭据落盘（XDG 目录 0700 / 文件 0600 / 原子写）+

  （`from_overlay_and_live` 合并 live；models.dev 未收录 id 一律 `openai-compat` +

#### 权限 · 提问 · 会话 · 配置

- **资产完整性——逐请求校验 + 手动全量**（HTTP 层，纯加性）：静态面每请求核验本次将服务的

#### 运行可靠性（`glob` · 工具结果上限 · 生效模型回显 · 提问超时 · CLI · e2e 隔离）

- **工具结果上限**（`agentj-core` + `agentj-config`）：工具结果只在**唯一转换点**
  （`turn_runner.rs` 构造 `AgentEvent::ToolResult` 处）按字符预算截断一次——
  `budget::truncate_chars` 保留头部 `max_chars` 个字符（按 UTF-8 边界切分）并追加
  `…[已截断 {dropped} 字符，原文 {total} 字符；请缩小查询范围]…`；`[agent]` 新增
  `max_tool_result_chars`（默认 `100_000`，钳制 `1_000..=1_000_000`）；截断发生时内核发出
  `AgentEvent::ToolResultTruncated { tool_call_id, dropped_chars }`（内核内事件，不上 wire）。
- **`session/run` 回显生效 provider / model**（`agentj-protocol` + `agentj-core` +
  `agentj-ipc` + `@agentj/web`）：`ProviderRegistry` 加性补 `set_default` / `default_name` /
  `get_default_with_name`，`TurnRunner` 把本轮**实际生效**的 provider 名与 model
  （`default_options.model`）经 `AgentEvent::Done` 上抛；`SessionRunResult` 加性新增
  `provider` / `model`（`@since 0.19.0`，**未知时整键省略、绝不为 `null`**，见
  `docs/specs/ipc-protocol.md` §8.7）；轨迹新增 `TrajectoryValue::RunModel`
  （`kind: "run_model"`，每轮至多一条、紧随 `usage` 条目，两者皆未知时不落盘）；Web 运行详情
  右栏的模型标签在结果带值时显示内核回报的生效模型。
- **`glob` 改为进程内执行**（`agentj-tools`）：删除 `find` 子进程，新增进程内匹配器 / 遍历器
  （`glob.rs`：`globset` + `walkdir`）；**pattern 不含 `/` 时按路径分量的 basename 匹配，
  含 `/` 时按根相对全路径匹配**（`literal_separator(true)`：`*` 不跨 `/`、`**` 跨）；跳过目录
  沿用 `grep` 的同一份清单；输出 `./<相对路径>` 逐行、已排序、上限 `2000` 条（超出追加
  `# 已截断 N 条命中（上限 2000），请缩小 pattern`）；沿用 `timeout_ms`（默认 `60s`、钳制
  `1s–600s`），超时以 `glob timed out after Ns` 文本结果回报而非错误。
- **e2e 测试环境隔离**（`agentj-cli` tests）：新增共享 `TempEnv` 助手
  （`crates/agentj-cli/tests/common/mod.rs`）为子进程把 `HOME` / `XDG_DATA_HOME` /
  `XDG_CONFIG_HOME` 指向临时目录并移除凭据类环境变量
  （`AGENTJ_OPENCODE_GO_API_KEY` / `AGENTJ_E2E_KEYLESS` / `AGENTJ_MISSING_KEY`），
  `e2e_cli` / `e2e_permission` / `e2e_auth` / `e2e_serve` 全部改用——测试不再读写真实 `~`。
- **`ask` 默认超时**（`agentj-config` + `agentj-question`）：新增 `[agent] question_timeout_s`
  （默认 `600`，钳制 `1..=86_400`），CLI 把它注入 `QuestionModule::set_default_timeout_s`——
  未显式给 `timeout_s` 的提问不再无限等待，超时后按 **skipped** 结算（未送达 owner 的提问
  立即 skipped，语义不变）。
- **CLI 审批与配置校验**（`agentj-cli` + `agentj-config`）：`run --yes` 的审批器在 stderr 打印
  `auto-approved <tool> (--yes)` 后直接批准；TTY 下审批提示 `approve <tool>? <精简参数>`
  （`command` / `pattern` / `path` 取其一、折叠空白、超 200 字符省略）+ `  reason: <原因>` +
  `[y/N] ` 同步打到 stderr，另起线程读 stdin 解码（`y` / `yes` 批准，其余含 EOF 一律拒绝）；
  非 TTY 且未加 `--yes` 时不读 stdin、也不挂审批器，待决请求仍按 `[permission] timeout_ms`
  预算自动拒绝；`[permission] timeout_ms` 越界值钳制到 `100..=600_000` 并在 stderr 警告
  （省略 = `60_000`）。

### Changed

- **TUI 文件搜索改为消费内核的服务端排名**（`@agentj/tui`）：排序不再由客户端重算，
  而是直接渲染内核 `file/list { query }` 返回的顺序与 `total`；旧内核（回复不含 `total`，
  即忽略 `query`）时显示「不支持服务端搜索」提示并以空结果呈现，不再本地兜底排名。
- **Web 工具调用卡片**（`@agentj/web`）：对话中栏的工具卡片在工具名旁显示本次调用的目标
  ——`bash` 的命令、`read` / `write` 的文件路径、`glob` / `grep` 的匹配模式（`grep` 附带
  `include`）；超长值以省略号截断而不换行。卡片宽度由「按内容收缩」改为铺满中栏宽度。
  （无协议变更。）
- **前端包管理收敛为 npm 单一 lockfile**（`agentj-ui`）：删除 `agentj-ui/bun.lock` 与
  `apps/web`、`packages/protocol` 各自的 `package-lock.json`，只保留
  `agentj-ui/package-lock.json`；`agentj-ui/package.json` 补 `name` / `version` / `private` /
  `packageManager: npm@11.11.0` / `engines.node >= 24`，`apps/web` 与 `apps/tui` 的版本从
  `0.0.0` 对齐到 `0.1.0`；`.npmrc` 固定 registry 镜像（lockfile 的 integrity 与 registry 无关，
  可随时改回官方源）。
- **覆盖率门禁改为棘轮**（`.github/workflows/ci.yml`）：`COVERAGE_THRESHOLD` 由静态 `50` 改为
  按实测基线推导的 `92`（2026-10-23 实测行覆盖 `93.67%`，公式 `max(50, floor(X) - 1)`），

- **版本一致性脚本覆盖面扩大**（`scripts/check-version.sh`）：新增 `AGENTJ_ROOT` 覆盖、

  `node_modules/`、`.playwright-mcp/`（107 文件）；`.gitignore` 补 `.opencode/`
  （AI 工具运行时状态，机器本地）。
- **陈旧 lockfile 导致的依赖解析漂移**：三份 lockfile 并存已消除（见 Changed），
  `npm ci` 在 `agentj-ui` 根一键可复现。
- **`scripts/check-relocate.mjs` 引用了已改名文件**：原先断言
  `agentj-ui/apps/web/src/jsonrpc.test.ts` 存在，该文件早已拆分改名 → 脚本必然失败；改为断言
  `apps/web/src` 下至少存在一个 `*.test.ts(x)`，随后接入 CI。
- **`serve` 收到 SIGTERM 偶发未走优雅关闭**（`agentj-cli`）：`spawn_signal_task` /
  `spawn_tcp_signal_task` 把 `tokio::signal::unix::signal(...)` 写在 `tokio::spawn` 的 async 块内，
  而 tokio 只在 `signal()` **首次被调用**时安装进程级 OS 处理器、`tokio::spawn` 又是惰性的——在任务
  首次被 poll 之前到达的 SIGTERM 仍按默认处置杀死进程（以信号 15 退出、不走优雅关闭链），在
  llvm-cov 插桩构建等启动较慢的环境下表现为偶发失败。现在 stdio 与 TCP 两条路径都在 spawn **之前**
  同步创建首等待的 `SIGINT` / `SIGTERM` 流（`SignalKind::interrupt()` 与 `ctrl_c()` 等价），处理器
  必然先于 `serve_stdio()` / `tcp.run()` 安装；TCP 的第二次信号（强制退出 `exit 130`）仍保持惰性
  创建，语义不变。TCP 侧还要求处理器先于**就绪输出**安装：`serve_tcp()` 原先在
  `println!("listening on …")` 与 `startup_warnings()` 循环**之后**才创建信号任务，按就绪行立刻发
  SIGTERM 的监督者（systemd 式）仍会命中默认处置（实测旧码 40 次中 8 次以信号 15 退出）；现在信号
  任务紧随 `TcpIpcServer::bind()` 创建，就绪宣告之后不再有窗口。
- **进程型工具的执行生命周期互不一致**（`agentj-tools`）：`bash` / `grep` 原先各自裸调
  `std::process::Command`——既无超时也不隔离进程组，长命令会累积孤儿 / 僵尸进程；而
  `execute_with_timeout` 的「超时返回、子进程继续跑」语义并不能真正止损。现在两者统一经
  `ToolExecutor`（独立进程组 + 超时杀整组 + drop 回收），超时可经入参 `timeout_ms` 覆盖
  （`bash` 默认 120s，`grep` 默认 60s；钳制 1s–600s），超时后模型收到明确超时错误
  而不是无限挂起。（`glob` 随后改为进程内执行，超时以文本结果回报而非错误，见上文「`glob`
  改为进程内执行」。）
- **Web 对话出现无文字的空助手气泡**（`@agentj/web` + `agentj-ipc`）：部分网关在工具调用之间把
  孤立的零宽空格（U+200B）当作保活增量流式下发；U+200B 不具备 Unicode `White_Space` 属性，
  `trim()` / `is_whitespace()` 都不会判空，于是每一帧都渲染成一个只有左侧强调线、没有任何文字
  的气泡（多轮工具调用之间尤为明显）。现在前端（新增 `blankText.ts`）丢弃视觉上为空白的助手
  条目与 thinking 节点（live 帧、历史回放、已存轨迹一致生效），内核 `flush_thinking` 也不再把
  「仅空白 / 零宽 / BOM」的 thinking 落盘。
- **Web 左侧会话列表不刷新**（`@agentj/web`）：会话列表过去只在挂载时拉取一次，新建会话
  （`+ 新建会话`）或一轮对话结束（会话 preview / `updated_at` 变化）后都不出现在左栏，除非刷新
  页面或重连。现在 `session/new` 成功后与每次 turn 结算（新增 `agentj:sessions-updated` 事件，
  成功与失败都会广播）都会重新拉取 `session/list`。
