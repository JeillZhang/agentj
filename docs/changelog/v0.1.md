# v0.1.x —— 全部特性

> 发布：0.1.0（2026-10-18，功能）
> 协议：`PROTOCOL_VERSION` **0.18.0**（28 方法 / 78 schemas / 18 crates）

本文档是 **`0.1.0` 的完整特性清单**：项目全部能力合并于 `0.1.0` 一个版本，不再按历史小版本
拆分。用户可见特性见 [`docs/guide/`](../guide/)，协议契约见
[`docs/specs/ipc-protocol.md`](../specs/ipc-protocol.md)。

## 0.1.0 —— 内核 + 全端（功能）

### Added

#### 内核与协议

- **IPC 协议契约**（`agentj-protocol`）：JSON-RPC 2.0 信封 + 错误码 + 28 方法 params/result +
  流式/订阅/权限/提问/文件列举/订阅服务类型；78 JSON Schema（schemars 生成 + 漂移门禁）+
  方法注册表 `protocol/methods.json` + 跨语言类型绑定 `@agentj/protocol`；人类可读规范
  `docs/specs/ipc-protocol.md`。协议版本 **0.18.0**。
- **内核**（`agentj-core`）：Kernel 混合总线 + 模块 trait 注册表 + ServiceRegistry（同步/异步）
  + TurnRunner 总线化 turn 编排；EventBus 订阅/发布 + 重入防护（`EventGuard` thread_local /
  `MAX_EVENT_DEPTH=16`）。
- **Agent 循环（流式）**：`AgentLoopModule` + `ToolExecutorModule` + `SubAgentService`。
- **token 预算**（`budget`）：请求前 `estimate_tokens` 估算 + `fit_messages` 裁剪 + 上游超限
  `retry_budget` 收紧重试（`ContextPipeline::fit` 默认接入）。
- **文本工具调用还原**（`text_tool_call`）：把模型写成纯文本方言的工具调用无歧义还原为真实调用；
  无法还原时纠偏重发并如实报错，不把标记当结论。
- **TurnArtifact**：FileChange / Todo 产出 + 自研 unified diff（per-run `run_id` / `seq`）。
- **ToolCallContext**：会话根上下文，工具相对路径重定基。

#### 内置工具与扩展

- **内置工具**（`agentj-tools`）：`bash` / `glob` / `grep` / `read` / `write` / `todo`（共 6 个）；
  `grep` 优先 `rg`、缺失时回退进程内检索（`regex` + `globset` + `walkdir`）。
- **MCP**（`agentj-mcp`）：子进程 MCP 客户端 + `McpConnectionManager` 长驻连接。
- **上下文管线**（`agentj-context`）、**用量统计**（`agentj-stats`）、
  **Skills 加载器**（`agentj-skills`）。
- **插件系统**（`agentj-plugin`）：manifest + 状态机 + 依赖图 + libloading。
- **License**（`agentj-license`）：Ed25519 许可证校验（entitlements + free mode）。

#### 模型提供方

- **三线 wire-format + Mock + Ollama**（`agentj-model`）：OpenAI-compatible SSE /
  OpenAI Responses / Anthropic Messages / opencode-go / Ollama / Mock。
- **opencode-go 订阅**：`agentj auth` 凭据落盘（XDG 目录 0700 / 文件 0600 / 原子写）+
  RFC 8628 设备码授权 + `refresh::ensure_access`（单飞刷新、单次 refresh token 轮换、60s 安全
  余量、失败不落盘）+ live/overlay 动态目录（`data/opencode-go.json` 路由快照）+
  合规请求头（`agentj/<ver>` UA / `x-opencode-session`）+ 模型可见性。
- **路由与目录**：`console_catalog`（`GET /api/v2/config` 账号级目录）+ `catalog`
  （`from_overlay_and_live` 合并 live；models.dev 未收录 id 一律 `openai-compat` +
  `verified:false`，不猜路由）。
- **错误映射与重试**：`gateway_error`（429 → `RateLimited`、上下文超限 →
  `TokenLimitExceeded { used, max }`、其余 → `Api { status, message }`）；`retry`
  （`temperature` 被拒时去参数重试一次）。
- **用量**（`usage`）：防御式 `GET /v1/usage`（三窗口、未知键忽略、`percent==0` 占位 reset 丢弃）。

#### 权限 · 提问 · 会话 · 配置

- **权限系统**（`agentj-permission`）：决策引擎 + `ask` 60s 超时自动 Deny + `allow_always`
  会话级；`respond` / `cancel_session` 只投递决定、保留待决条目至工具消费（`PENDING_TTL`
  300s）；重复/迟到答复返回 `false`，不覆盖首次决定。
- **提问通道**（`agentj-question`）：`QuestionModule` + `AskTool`，镜像 permission 的
  pending/owner 归属；`ask_blocking` 阻塞等待、`respond` 幂等、`timeout_s` 可空。
- **会话**（`agentj-session`）：InMemory / FileBacked 存储 + 过期清理 + 会话级 `project_root`
  持久化 + 回放重建。
- **配置**（`agentj-config`）：TOML（`[model]` / `[agent]` / `[permission]` / `[session]` /
  `[license]` / `[web]` / `[[mcp.servers]]`）+ `toml_edit` 定点写回保留注释。

#### 服务与接入

- **JSON-RPC IPC**（`agentj-ipc`）：stdio + TCP 多客户端（NDJSON）+ WebSocket 网关（同端口复用 +
  混合分类器）+ per-session 路由 + `file/list` dispatch（沙箱 + git 状态 + `query` 子树搜索）+
  owner 断连结算（question / permission 待决项）+ `error.data` 透传。
- **内核托管 Web UI**（`web` 子模块）：同端口静态托管 + `/login` / `/logout` + 不透明会话 cookie
  + 同源 Origin 校验 + `next` 白名单（防开放重定向）+ WS cookie 第三通道鉴权
  （`?token=` / `initialize.token` / 登录 cookie 三通道）。
- **可观测性**：`GET /version`（`DistVersion` + `startup_warnings()`）、鉴权门控
  `GET /metrics`（Prometheus 文本 + 聚合计数 + per-IP Top-50 截断 + integrity 摘要）、
  `login_limiter`（按来源 IP 失败计数与指数锁定，`429 + Retry-After`）。
- **客户端 IP 派生（HTTP 层，opt-in）**：`[web] trust_proxy_headers`（默认 `false`）采信
  `X-Forwarded-For` / `X-Real-IP`——仅当直接 TCP peer 是回环时才生效，派生 IP 只用于限流键、
  per-IP 序列与日志，**永不参与鉴权**（回环免鉴权判据始终是真实 peer）；新增
  `agentj_web_client_ip_source_total` / `agentj_web_proxy_header_invalid_total`。
- **登录限流计数持久化**：限流状态跨重启存活——单文件快照
  `$XDG_DATA_HOME/agentj/metrics-state-<port>.json`（目录 `0700` / 文件 `0600` / 原子写 /
  `version: 1` / 上限 1 MiB），启动恢复、运行期 debounce 落盘、优雅退出强制落盘；新增
  `agentj_web_metrics_state_restored` / `agentj_web_metrics_state_entries_restored` /
  `agentj_web_metrics_state_write_failures_total` / `agentj_web_metrics_state_last_flush_unix`。
- **资产完整性**：构建期 `asset-manifest.json`（sha384 覆盖 dist 全部部署文件，与 SRI 逐字节
  一致）→ 启动逐文件校验 + 运行期游标轮转抽检（`SpotCheckConfig`）；抽检节拍改由 `[web]`
  `spot_interval_secs` / `spot_sample` 配置（默认仍 60s / 8 文件，行为不变）。
- **资产完整性——逐请求校验 + 手动全量**（HTTP 层，纯加性）：静态面每请求核验本次将服务的
  文件（按路径 memoize + **绝对 TTL**、缓存上限 1024、fail-open 不改响应、未鉴权零哈希），SPA 面
  未知路径回落 `/index.html`；`[web] verify_on_request`（默认开）/ `verify_cache_ttl_secs`
  （默认 60s）可调；`POST /integrity/verify` 同步全量核验（鉴权与 `GET /metrics` 一致，返回
  `manifest_present` / 计数 / 升序 `offenses` 上限 50 + `truncated` / `duration_ms`，空清单算

### Changed

- **TUI 文件搜索改为消费内核的服务端排名**（`@agentj/tui`）：排序不再由客户端重算，
  而是直接渲染内核 `file/list { query }` 返回的顺序与 `total`；旧内核（回复不含 `total`，
  即忽略 `query`）时显示「不支持服务端搜索」提示并以空结果呈现，不再本地兜底排名。
- **Web 工具调用卡片**（`@agentj/web`）：对话中栏的工具卡片在工具名旁显示本次调用的目标
  ——`bash` 的命令、`read` / `write` 的文件路径、`glob` / `grep` 的匹配模式（`grep` 附带
  `include`）；超长值以省略号截断而不换行。卡片宽度由「按内容收缩」改为铺满中栏宽度。
  （无协议变更；`PROTOCOL_VERSION` 仍 `0.18.0`。）

### Removed

- **TUI 与 mock kernel 的本地排名镜像**（`@agentj/tui`）：移除 `files.ts` 的
  `searchRank` / `filterEntries` / `comparePaths` 与 mock kernel 的 `rankFixtureEntry`，
  排名规则收敛为 Rust `file_list::search_rank` 单一真源。

### Fixed

- **`serve` 收到 SIGTERM 偶发未走优雅关闭**（`agentj-cli`）：`spawn_signal_task` /
  `spawn_tcp_signal_task` 把 `tokio::signal::unix::signal(...)` 写在 `tokio::spawn` 的 async 块内，
  而 tokio 只在 `signal()` **首次被调用**时安装进程级 OS 处理器、`tokio::spawn` 又是惰性的——在任务
  首次被 poll 之前到达的 SIGTERM 仍按默认处置杀死进程（以信号 15 退出、不走优雅关闭链），在
  llvm-cov 插桩构建等启动较慢的环境下表现为偶发失败。现在 stdio 与 TCP 两条路径都在 spawn **之前**
  同步创建首等待的 `SIGINT` / `SIGTERM` 流（`SignalKind::interrupt()` 与 `ctrl_c()` 等价），处理器
  必然先于 `serve_stdio()` / `tcp.run()` 安装；TCP 的第二次信号（强制退出 `exit 130`）仍保持惰性
  创建，语义不变。TCP 侧还要求处理器先于**就绪输出**安装：`serve_tcp()` 原先在
  `println!("listening on …")` 与 `startup_warnings()` 循环**之后**才创建信号任务，按就绪行立刻发
  SIGTERM 的监督者（systemd 式）仍会命中默认处置（实测旧码 40 次中 8 次以信号 15 退出）；现在信号
  任务紧随 `TcpIpcServer::bind()` 创建，就绪宣告之后不再有窗口。
- **进程型工具的执行生命周期互不一致**（`agentj-tools`）：`bash` / `grep` / `glob` 原先各自裸调
  `std::process::Command`——既无超时也不隔离进程组，长命令会累积孤儿 / 僵尸进程；而
  `execute_with_timeout` 的「超时返回、子进程继续跑」语义并不能真正止损。现在三个工具统一经
  `ToolExecutor`（独立进程组 + 超时杀整组 + drop 回收），超时可经入参 `timeout_ms` 覆盖
  （`bash` 默认 120s，`grep` / `glob` 默认 60s；钳制 1s–600s），超时后模型收到明确超时错误
  而不是无限挂起。
- **Web 对话出现无文字的空助手气泡**（`@agentj/web` + `agentj-ipc`）：部分网关在工具调用之间把
  孤立的零宽空格（U+200B）当作保活增量流式下发；U+200B 不具备 Unicode `White_Space` 属性，
  `trim()` / `is_whitespace()` 都不会判空，于是每一帧都渲染成一个只有左侧强调线、没有任何文字
  的气泡（多轮工具调用之间尤为明显）。现在前端（新增 `blankText.ts`）丢弃视觉上为空白的助手
  条目与 thinking 节点（live 帧、历史回放、已存轨迹一致生效），内核 `flush_thinking` 也不再把
  「仅空白 / 零宽 / BOM」的 thinking 落盘。
- **Web 左侧会话列表不刷新**（`@agentj/web`）：会话列表过去只在挂载时拉取一次，新建会话
  （`+ 新建会话`）或一轮对话结束（会话 preview / `updated_at` 变化）后都不出现在左栏，除非刷新
  页面或重连。现在 `session/new` 成功后与每次 turn 结算（新增 `agentj:sessions-updated` 事件，
  成功与失败都会广播）都会重新拉取 `session/list`。
