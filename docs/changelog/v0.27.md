# v0.27.x —— opencode-go 订阅二期（用量 / 设备码登录 / 账号级目录）

> 发布：0.27.0（2026-10-07，功能）· 0.27.1（2026-10-07，验收修复）
> 协议：`PROTOCOL_VERSION` **0.16.0 → 0.17.0**（新增 5 个方法 `model/list` /
> `auth/status` / `provider/usage` / `auth/deviceStart` / `auth/devicePoll`；
> 方法面 **21 → 26**、schema 总数 **52 → 72**，不新增错误码）

## 0.27.1 —— 验收修复（修复）

订阅二期验收发现的两个 wire 投影缺陷。

### Fixed

- **`CredentialKind` 的 OAuth 线值写成了 `o_auth`**：`#[serde(rename_all = "snake_case")]`
  把驼峰变体 `OAuth` 渲染成 `o_auth`（与一期凭据文件 `type` tag 同类缺陷，那个已在 0.27.0
  一并修掉，协议枚举漏修）。现固定为 **`oauth`**，与 `auth.json` 的 `type: "oauth"`、
  设计 §8.24 / §9.1 枚举表、计划 T16 AC 一致；`schemas/CredentialKind.json`（及
  `AuthStatusResult` / `CredentialInfo` / `AuthDevicePollResult` 的内联枚举）、
  `@agentj/protocol` 类型、Web 订阅面板与协议规范同步更新。
- **仅来自环境变量的 api_key 不投影凭据信息**：`auth/status` 在凭据仅来自
  `api_key_env`（`auth.json` 无对应条目）时返回 `authenticated: true` 却省略 `credential`，
  丢失 `kind` / `source` / `key_hint`。现在 env 来源也会返回
  `{kind:"api_key",source:"env",key_hint:"…<末4位>",expiring_soon:false}`；
  file api_key 与 OAuth 两条既有路径行为不变。

## 0.27.0 —— opencode-go 订阅二期（功能）

一期（v0.25.x）交付了凭据生命周期、动态目录、合规请求头与模型可见性；二期把订阅做成
**可运维**：看得到用量、用设备码登录、拿到账号级真实目录，并让 access token 仅 600s 的
OAuth 凭据在长驻内核里自动保鲜。全部 wire 变更为**加性**，此前客户端零破坏。

### Added

- **用量面板**：内核新增 `provider/usage`，返回三个窗口（`rolling` 滚动 5 小时 /
  `weekly` / `monthly`）的 `{kind, status, percent, resets_at}`；`percent` 是**已用**百分比，
  **无余额 / 剩余额度字段**。上游形状漂移时防御式解析（未知窗口键忽略、`status` 未知值容错、
  `percent` 非整数则该窗口降级、`usage` 缺失则 `error.kind="unavailable"` 而不编造百分比）；
  `percent == 0` 时省略 `resets_at`（上游占位值会误导用户）。进程内 TTL 缓存 **300s**、
  `refresh:true` 强制绕过、无常驻轮询任务。
- **配额预警**：阈值由内核配置 `[model] quota_warn_percent`（int，默认 **80**，clamp `1..=100`）
  随 `provider/usage` 结果下发（`warn_percent`），Web/TUI 三处口径一致。两个触发点：
  订阅面板内任一窗口 `status == "rate-limited"` 或 `percent >= warn_percent` 时以警示样式展示；
  一轮 run 收到 `429`（文案含 `GoUsageLimitError`）时，Web 运行面板在该消息旁给一次性提示
  「可能是订阅额度受限 → 设置 · 订阅」。
- **设备码登录（RFC 8628）**：`agentj auth login --device`（与 `--api-key` 互斥）打印
  `verification_uri` 与 `user_code`、按上游 `interval` 轮询、`slow_down` 时自动延长等待、
  授权成功即写入 `auth.json`（目录 `0700` / 文件 `0600` 原子写）并打印「已登录 …（已替换原有凭据）」
  与凭据文件路径；设备码用尽 / 被拒 / 未识别错误均以可行动文案失败且**不写盘**。
  内核侧新增 `auth/deviceStart` + `auth/devicePoll`（无状态：`device_code` 由客户端持有并回传；
  `pending` / `slow_down` 是**成功响应**而非错误），CLI 与 Web/TUI 共用同一套
  `agentj-auth::oauth` 流程。退出仍是 `agentj auth logout`。
- **账号级模型目录 `model/list`**：三层来源 `account` → `live` → `overlay`
  （非 opencode-go provider 为 `static`，不发网络请求）。账号级 `GET /api/v2/config`
  （`Bearer <key|access>`，OAuth 凭据额外带 `x-org-id`）反映 workspace 真实可选项，
  因此**工作区被禁用的模型不会出现**；逐层回退全部静默（`source` 字段如实标注层级）。
  账号级 / live 的 id 若未命中 overlay，合成为 `openai-compat` + `verified:false`
  （绝不按名字猜路由）。进程内复用窗口 **60s**，`refresh:true` 强制绕过。
- **凭据状态 `auth/status`**：纯读投影，**绝不轮换 token、绝不发网络请求**——
  api_key 给出 `key_hint`（`redact()` 输出，形如 `…1234`），OAuth 给出 `org_id` +
  `expires_at` + `expiring_soon`（剩余 < 120s 为 true），另带 `authenticated` 与
  `models_count`。完整密钥 / token 永不出现在 wire 上。
- **OAuth 长期可用**：新增 `agentj-auth::refresh::ensure_access`（余量 60s 判定 + 单飞刷新 +
  `auth.json.lock` 文件锁串行化 + 重读校验），内核与 CLI 在每次使用凭据前调用；refresh token
  **单次使用**（复用即吊销整个会话），刷新失败给出可行动错误而**不回落空 Bearer / 旧 token**。
- **Web 订阅面板**：`SettingsDialog` 新增「订阅」tab（`subscription` 分类）→ `SubscriptionPanel`
  （三窗口用量行 + `rate-limited`/超阈值警示样式 + 凭据状态 + 设备码登录 / 轮询状态机 +
  `error.kind` 文案矩阵 + 关闭面板即停止轮询），复用既有 `ModalDialog` 与 `useRovingFocus`。
- **TUI 订阅浮层**：palette 新增 `subscription` 命令 → `SubscriptionOverlay`
  （同内容文本版：`j/k` 滚动、`Enter` 触发登录 / 刷新、`Esc` 关闭；交互期全局键盘处理早退）。
- **SDK / 前端契约**：`@agentj/sdk` 的 `METHODS` 与 `@agentj/protocol` 的 `types.d.ts`
  按新注册表重新生成（21 → 26 方法）。

### Changed

- **版本 bump**：工作区 `0.26.0` → **`0.27.0`**（功能 = minor）；`PROTOCOL_VERSION`
  `0.16.0` → **`0.17.0`**（`protocol/methods.json` + `schemas/*.json` 同步）；SDK `VERSION`、
  desktop 三清单（`package.json` / `tauri.conf.json` / `src-tauri/Cargo.toml`）与三个 lockfile
  的版本元数据、`scripts/check-version.sh` 的期望值同步。
- **OAuth 凭据可用**：一期把 `type:"oauth"` 的条目判定为 `unsupported credential type 'oauth':
  requires agentj phase 2 or newer` 而拒绝使用；本版本 `Credential::key()` 对 OAuth 返回
  **access token**（格式与 `auth.json` 布局不变），`AuthError::Unsupported` 只留给真正未知的
  `type` 标签。
- **`agentj-auth` 新增依赖**：`reqwest`（json）+ `tokio`（macros / rt / time）+ `async-trait`
  （与 workspace 既有声明同版本，无新外部 crate 版本漂移）；`agentj-auth` 由此从纯本地凭据库
  升为「凭据 + OAuth 设备流 / 刷新」模块，`Cargo.lock` 相应刷新。
- **刷新装饰器**：`agentj-cli` 的 `RefreshingProvider` 包住 provider，`chat` / `chat_stream` 前
  先 `ensure_access`——凭据未变则零重建直接委托，凭据变更则用新密钥经 `ProviderFactory`
  重建内层 provider 换入（约每 10 分钟一次），刷新失败返回可行动错误
  （`…需重新登录：agentj auth login --device`）。`models()` 仍走本地目录，不触发刷新、
  不因凭据失效而变空。因此**登录后无需重启内核**。
- **新配置键**：`[model] quota_warn_percent`（默认 80，越界 clamp 到 `1..=100`）与
  `[model] console_base_url`（默认 `https://opencode.ai/console`，供别名 / 自建代理排障）。
- **文档**：订阅指南重写（用量语义、设备码登录、控制面基址、模型目录三层来源、排障文案）；
  协议规范补 §8.23–§8.27 与 §3.4 / §9 / §10 / §11.3 的 0.17.0 条目；`AGENTS.md` / `README.md`
  基线同步为 `0.27.0` / `PROTOCOL 0.17.0` / 26 方法。

### Fixed

- **控制面基址修正**：一期文档写的 `console.opencode.ai` 只是别名，实际基址为
  **`https://opencode.ai/console`**（`OPENCODE_CONSOLE_BASE`）；文档、设备码示例与配置默认值
  统一到该基址。
- **TUI 不再伪造缺失的用量百分比**：`percent` 缺席时显示为未知而不是按 `0%` 渲染，
  与内核「不编造窗口 / 百分比」的语义对齐。

### 已知边界（未做）

- 不做多账号 / 账号切换（同一 provider 再次登录 = 替换）；不做 OS keyring；
  不做按量付费 Zen（`/zen/v1`）；设备登录的最终授权永远发生在用户自己的浏览器会话中，
  新增的 5 个方法**不加额外权限门**（沿用既有 WS token / cookie / 回环鉴权边界）。
- 不在顶栏 / 状态栏做常驻配额徽标（避免引入周期轮询或未定义的新鲜度语义）。
