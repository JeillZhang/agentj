# v0.28.x —— CLI run 的 per-run 模型/provider 覆盖

> 发布：0.28.0（2026-10-08，功能）
> 协议：`PROTOCOL_VERSION` **0.17.0**（不变——`provider` / `model` 自 0.16.0 起已是
> `session/run` 的可选字段，本版本零 wire 变更）

## 0.28.0 —— CLI run 的 per-run 模型/provider 覆盖（功能）

`agentj run` 此前无法选择模型：内嵌路径恒用配置声明顺序中首个成功注册的 provider 与
`[model].default_model`，`--attach` 路径根本不在 `session/run` 里携带覆盖。本版本给 CLI
补上 `--provider` / `--model`，让「单次 prompt」与 Web / TUI 具备同一能力。

### Added

- **`agentj run --provider <NAME> --model <MODEL_ID>`**：两者均为可选长选项、相互独立
  （`--model` 可单独使用，保留默认 provider）；只对本次运行生效，不写配置、不进入会话。
- **两条路径一致**：内嵌路径经 `IpcServer` 新增的公开入口
  `run_turn_stream_with(sid, input, RunOverrides)` 传入覆盖；`--attach` 路径在
  `session/run` 的 params 中仅于提供时携带 `provider` / `model` 键。
- **空白值等同缺省**：`--provider ""` / `--provider "   "`（`--model` 同理）按「未提供」处理，
  由内核回落到默认 provider / `[model].default_model`；未知 provider 不回落，运行失败。

### Changed

- **内嵌 `run` 失败时退出码 `0` → `1`**：此前遇到 `AgentEvent::Error` 仍打印空行并以 0 退出；
  现在先完成内核 / MCP 清理，再在 stderr 打印一行 `error: <文本>` 并以退出码 `1` 结束，
  stdout 不再出现最终回答。
- **`--attach` 不再吞掉 JSON-RPC `error`**：此前错误响应分支缺失，进程会一直等待；现在
  `-32603` 映射为 `error: <message>`，其它错误码附 `(code <code>)`，随后退出码 `1`。
