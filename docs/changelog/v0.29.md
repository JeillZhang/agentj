## 0.29.3 —— `/v1/messages` 鉴权头修复（修复）

opencode-go 的 anthropic 路由（`claude-haiku-5-5` / `minimax-m2.7` / `minimax-m3` /
`qwen3.7-plus` / `qwen3.8-flash` / `qwen3.8-max`）此前发 `Authorization: Bearer`，而实测
`POST /zen/go/v1/messages` **只认 `x-api-key`**，请求会被 401 挡下。

### 实测口径（2026-10-09 匿名探测，以 `Missing API key.` / `Invalid API key.` 区分「未读到凭据」/「读到但无效」）

| 端点 | `Authorization: Bearer k` | `x-api-key: k` |
|---|---|---|
| `/v1/messages` | 401 `Missing API key.` | 401 `Invalid API key.` |
| `/v1/responses` | 401 `Invalid API key.` | 401 `Missing API key.` |
| `/v1/chat/completions` | 401 `Invalid API key.` | 401 `Missing API key.` |
| `/v1/usage` | 401 `Unauthorized`（读到） | 401 `Missing API key.` |
| `{console}/api/v2/config` | `Bearer`（既有，未变） | — |

### Fixed

- **`AnthropicProvider` 补齐 `x-api-key`**：新增 `auth_headers()`（单一发送点，`chat` 与
  `open_stream` 共用）——同时发 `x-api-key`（Anthropic 与 opencode-go 网关要求的凭据位）与
  `Authorization: Bearer`（兼容只认 bearer 的第三方 anthropic 兼容网关），并保留
  `anthropic-version: 2023-06-01`；原先两处重复的头部拼装同步消除。
- 单测由「只断言 `Authorization`」改为**同时断言 `x-api-key` 与 `Authorization`**——此前用同形
  假头部匹配的 wiremock 用例掩盖了该缺陷。
- 未改动 `/v1/responses`、`/v1/chat/completions`（认 Bearer）与 `/v1/usage`（`bearer_auth`，实测一致）。
- 协议 wire 面不变；工作区 **0.29.2 → 0.29.3**。

## 0.29.2 —— opencode-go 路由改为 API 派生（修复）

opencode-go 的 `format`（三线端点路由）原来自仓库提交件 `models/opencode-go.json`，而该表由
`gen_opencode_catalog` 里一份**手写的 20 条 id → format 种子**维持。核对结论：`GET
/zen/go/v1/models` 只回 id（45 条，字段仅 `id/object/created/owned_by`），不含端点元数据；而
models.dev（`https://models.dev/api.json`）的 `opencode-go.models.<id>.provider.npm` 与官方
[端点表](https://opencode.ai/docs/go/#api-endpoints)「AI SDK 包」一列逐条对应（12/12 非 chat
模型零冲突，20 条 chat 模型经 provider 级默认继承吻合）——即端点路由完全可由公开 API 派生。

### Fixed

- **生成器读错 models.dev 路径（静默失效）**：`catalog_gen::dev_format` 读
  `models.<id>.npm`，真实形状是模型级 `models.<id>.provider.npm` 覆盖 + provider 级 `npm`
  默认继承（`@ai-sdk/openai-compatible`）。该分支因此**恒为空**，全部路由实际靠手写种子兜底；
  旧单测 fixture 用了同形状的假数据，掩盖了这一点。现按「模型级覆盖 → provider 默认」解析。
- **7 个官方在售模型此前路由到错误端点**：`claude-haiku-5-5`、`qwen3.8-flash`（应
  `/v1/messages`）与 `grok-4.6`、`grok-4.7`、`gpt-6-luna`、`muse-spark-1.2/1.3-contributor`
  （应 `/v1/responses`）不在旧快照中，被合成为 `openai-compat` → `/v1/chat/completions`。
  快照重新生成后逐条覆盖，并由 `catalog_lookup_routes_formats` 锁定。

### Changed

- **手写路由表整体删除**：`gen_opencode_catalog` 的 `overrides()` 20 条种子移除；端点配置不再有
  任何手写数据，唯一真源 = live id 列表 + models.dev npm 元数据。
- **产物迁入 crate**：`models/opencode-go.json` → `crates/agentj-model/data/opencode-go.json`
  （生成物；`include_str!("../data/...")` 去掉跨 crate 的 `../../../` 反向引用，根目录 `models/` 删除）。
- **`CatalogEntry.endpoint` 删除**：该字段从未被消费（各 transport 自己持有 `/v1/...` 路径），属
  重复的端点配置；快照不再写 `endpoint`。
- **base_url 单一真源**：新增 `agentj_model::catalog::OPENCODE_GO_BASE`，`agentj-cli` 的
  `OPENCODE_GO_BASE` / `BUILTIN_OPENCODE_GO_BASE` 改为引用它（原先两处字面量重复）。
- **未收录 id 不再猜测**：models.dev 未收录的 id 一律 `openai-compat` + `verified:false`
  （当前 10 条：`deepseek-flash` / `glm-5` / `glm-5.1` / `hy3-preview` / `kimi-k2.5` /
  `mimo-v2-omni` / `mimo-v2-pro` / `minimax-m2.5` / `omen-alpha` / `qwen3.5-plus`）。
  其中 `qwen3.6-plus` / `qwen3.7-max` 按 models.dev 判为 `openai-compatible`（旧手写表标
  anthropic）——**仅这两条路由发生变更**，如实测不符可临时加回种子。
- 协议 wire 面零变更（`format` 取值集合、`verified` 语义、`source` 层级不变）；
  工作区 **0.29.1 → 0.29.2**。

## 0.29.1 —— 验收修复（修复）

- **BUG-001（high，验收发现）**：`api_key_env` 非空（env 遮蔽）时，`auth/setApiKey` 结果与
  `auth/status` 都按 `env > auth.json` 报告 `effective_source` / `source = "env"`，但运行期
  注册仍使用**刚提交的 key**，导致 `session/run` 实际发送提交值——与读侧承诺相反。修复：
  `save_link()` 改用解析后的**生效凭据**（`env > 文件`，与启动路径 `build_providers` 一致）
  激活 provider，并让链接结果的 `credential.key_hint` 与 `effective_source` 描述同一生效凭据。
  新增回归测试 `env_shadow_key_is_what_the_registered_provider_sends`。协议面不变。

## 0.29.0 —— Web/TUI 链接 opencode-go API Key（功能）

订阅二期（v0.27.x）给了设备码登录与账号级目录，但「链接 API Key」这条官方路径（用户从
opencode.ai 控制台复制 key 粘贴进 AgentJ）此前只能靠手写 `auth.json` 或环境变量，而且
「链接后是否真的在跑」要等重启内核。本版本把 API Key 链接做成两端一等能力：一次调用
完成**校验 + 落盘 + 运行期激活 + 账号目录回传**，Web 与 TUI 都能输入、看到三态（已校验 /
未校验 / 已拒绝）并随时解除链接。全部 wire 变更为**加性**，此前客户端零破坏。

### Added

- **IPC 方法 `auth/setApiKey` / `auth/clearCredential`**（`@since 0.18.0`，契约见协议规范
  §8.28 / §8.29）：一次 `GET {console}/api/v2/config` 同时完成校验与目录，结果三态——
  `verified`（落盘 + 激活 + `source:"account"` + 播种 60s 模型缓存）、`unverified`（超时 /
  网络不可达 / 5xx / 畸形响应：**仍然落盘**并标注未校验，目录退到 live ∩ overlay，绝不
  编造）、`rejected`（401 / 403：**不落盘、不注册**，`error.kind` ∈ `unauthorized` /
  `entitlement`，文案内核自产、不回显上游正文）；参数非法（空 key / 未知 provider /
  非 opencode-go）仍走 `-32602` + `error.data.reason`（`invalid_params` /
  `unknown_provider` / `unsupported_provider`）。`auth/clearCredential` 移除凭据，并按
  剩余凭据收敛注册（仍有 env key → 重建；无 key → 注销），无条目时返回
  `cleared:false` 的成功响应。
- **运行期激活（无需重启内核）**：链接成功立刻重建并**替换注册** opencode-go provider，
  同时失效该 provider 的模型 / 用量缓存；设备码登录 `auth/devicePoll` 的 `authorized`
  分支复用同一激活路径（顺带修掉「Web 登录后仍要重启才能跑」的既有缺口）。
- **内置 opencode-go provider 条目**：用户 config 未声明 `kind = "opencode-go"` 时自动追加
  `base_url = "https://opencode.ai/zen/go"`、无 `api_key_env` 的内置条目（显式配置优先、
  不写用户 TOML）；无凭据时跳过并附「可在设置 · 订阅中链接 API Key」指引。
- **Web 设置 · 订阅新增「链接方式」区块**：`type="password"` + `autoComplete="off"` 的遮蔽
  输入、链接 / 解除链接按钮、三态回显、「将替换现有 OAuth 凭据」提示、
  `effective_source=env` 时显式提示「环境变量当前优先」；不写 `localStorage`、提交后清空
  输入框；设备码登录保留为次选。
- **TUI 订阅 overlay 新增链接模式**：`i` 进入输入、`Enter` 提交、`Esc` 取消，输入只渲染
  遮罩字符（帧内不出现明文），同样回显三态与 env 优先提示，并说明凭据写入
  **所连接内核所在的机器**。
- **文档与绑定**：协议规范补 §8.28 / §8.29 与 §3.4 / §9.1 / §10 / §11.3 的 0.18.0 条目；
  订阅指南按新路径重写；`@agentj/protocol` 类型与 `@agentj/sdk` `METHODS` 重新生成
  （28 条）。

### Changed

- **opencode-go 的 composer 模型列表改由账号目录驱动**：Web 链接成功（或
  `model/list {refresh:true}`）返回的目录作为**覆盖层**按 provider 替换条目（不追加重复
  项），用户未显式选择时自动选中首个账号条目；`kernel/status` 仍作连接期初值，该选择
  只作用于当前会话的 per-run 覆盖（**不改 `config.toml`**）。
- **协议版本 `0.17.0` → `0.18.0`**、方法面 26 → 28、schema 72 → 78；工作区
  `0.28.0 → 0.29.0`。`kernel/status` 与既有方法 / 字段的语义逐字不变。

### 已知边界（未做）

- **链接期间的时序**：替换 / 注销注册与并发 `session/run` 之间没有全局互斥——**进行中的
  那一轮 run 可能仍使用旧凭据，新凭据从下一轮生效**。
- **写入目标**：凭据写入**当前连接内核所在机器**的 `auth.json`；`--attach` / 远程 `serve`
  场景下即远端主机，非回环 `serve --host` 必须配 `--token`（既有要求，文档重述）。
- **不泄露**：结果只经 `redact()` 暴露 `key_hint`，完整 key 不出现在结果 / 日志 / 错误文案 /
  前端持久化中；两个方法**不新增权限门**（与既有 `session/run` 同级）。
- 不做多账号 / 账号切换（同一 provider 重复链接 = 替换）；不做 OS keyring。
