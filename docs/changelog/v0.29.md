## 0.29.7 —— 上下文预算：超限请求先裁剪再发送（修复）

长会话把整段历史与每轮工具结果**原样**发给上游，直到网关以 400
`[context_length_exceeded] ... your messages resulted in 3904559 tokens` 拒绝，用户
只能看到一个无法自助解决的 `-32603`。根因是内核此前**没有任何上下文管理**：
`ContextPipeline::assemble` 返回全量历史，`turn_runner` 每轮工具迭代继续追加（最多
`agent.max_tool_iterations` 轮），`ModelError::TokenLimitExceeded` 与
`SessionStore::estimate_tokens` 都是从未被构造/调用的死代码。现补齐预算：发送前裁剪，
上游仍报超限时收紧预算重试。协议 wire 面**不变**（`PROTOCOL_VERSION` 仍 **0.18.0** /
28 方法 / 78 schemas）。

### Fixed

- **请求无 token 预算**（`crates/agentj-core/src/budget.rs`，新增）：`estimate_tokens`
  （ASCII 约 4 字符/token，非 ASCII 按 1 字符/token——中文按字计费，宁可高估）、
  `message_tokens`（含工具调用参数）、`request_tokens`、`clamp_budget`、
  `retry_budget`、`fit_messages`。裁剪保留 system 与最新消息，单条超长正文头尾保留并标注
  「已截断 N 字符」；正文为空但工具调用参数超大的消息，整段参数改为
  `{"_truncated": "…[已截断 N 字符]…"}`（否则单条仍可远超预算）；且不会留下缺少对应
  assistant 调用的 `tool` 结果（否则上游 400）。
- **管线与发送路径未接预算**（`crates/agentj-core/src/{module.rs,turn_runner.rs}`）：
  `ContextPipeline` 新增默认方法 `fit(messages, budget_tokens)`，因此所有实现（含测试
  stub）默认受约束；`turn_runner` 每次发送前调用 `fit`，并在上游返回
  `TokenLimitExceeded` 时按 `retry_budget` 收紧后重试：优先取上游窗口 × 0.9，否则取当前
  预算 × 0.9，**保证严格变小**；已到 `MIN_CONTEXT_TOKENS`（无法再减）时不再重试，最多 2 次。
- **上下文超限未被识别为类型化错误**（`crates/agentj-model/src/gateway_error.rs`）：
  新增 `context_overflow(status, body)`（400/413 + `context_length_exceeded` /
  `maximum context length` / `reduce the length of the messages` 等措辞；**刻意不含**宽泛的
  `context window`，否则 `max_tokens` 超窗的参数校验错误会被误判成可裁剪重试）并从报文中
  解析 `(used, max)`（容忍 `1,048,576` 这类千位分隔；解析不到记 0），`api_error` 据此返回
  `ModelError::TokenLimitExceeded`；三种 wire 共用，用户可读文案为
  `context length exceeded: 3904559/1048576 tokens`。
- **预算不可配置**（`crates/agentj-config/src/{lib.rs,merge.rs}`）：新增
  `[model] max_context_tokens`（默认 `128000`，取值钳制到 `1000..=10000000`）与合并规则
  （文件值非默认时覆盖 base）。
- **`e2e_ws` 端口竞态**（`crates/agentj-cli/tests/e2e_ws.rs`，**非本缺陷引入**）：测试先
  绑定 `:0` 取空闲端口再拉起 `serve`，并行套件会抢占该端口导致
  `server did not start listening`（本地基线复现 1/3，本分支 2/3）。改为 `serve --port 0`
  并从 stdout 读回实际绑定地址（与 `e2e_serve.rs` 同款），消除竞态。

### Tests

## 0.29.6 —— 断连重连后的 `SessionBusy`（修复）

客户端断连后 run 按设计**继续执行**（`docs/specs/ipc-protocol.md` 异常断开一节：断线
客户端的 run 不中断，重连者用 `session/subscribe` 观测而非重试），但内核与 Web 两侧都
没跟上这条契约：内核侧（a）owner 连接断开时**未结算该会话的待审批权限**，孤儿 run 只能
等 `[permission] timeout_ms`（默认 60s）到点自动拒绝才继续，多轮工具调用可反复叠加
（最多 `agent.max_tool_iterations` 轮）；（b）审批请求找不到 owner 连接时直接丢弃，同样干等
到超时。客户端侧 Web 重连后**不重新 `session/subscribe`**，把仍在运行的 run 显示成
「任务中断」，用户点继续即撞上同会话并发互斥 `-32805 SessionBusy`。现按契约补齐：
断连即结算该 owner 的待审批项、无 owner 可达时立即拒绝、重连即重新订阅。协议 wire 面
**不变**（`PROTOCOL_VERSION` 仍 **0.18.0** / 28 方法 / 78 schemas）。

### Fixed

- **owner 断连后待审批权限不结算**（`crates/agentj-ipc/src/lib.rs`）：新增
  `IpcServer::settle_owner_pending(conn_id)`，把该连接所拥有会话的 question 与 permission
  待决项一并结算（permission 用新常量 `DISCONNECTED_REASON = "disconnected"`），并在连接
  结束的**每条**收尾路径上调用（EOF / 传输错误 / shutdown），早于等待在飞 run 结束的排空
  循环；`cleanup_connection` 复用同一逻辑。同时新增
  `ConnectionRegistry::clear_owner(conn_id)`，在排空前即撤销该连接的 session 归属，使排空
  期间新发起的审批请求也走「无 owner」分支立即被拒绝（而不是发给已消失的连接再干等一整个
  审批超时）。原先孤儿 run 会阻塞整个审批预算。
- **审批请求无 owner 可达时不再静默丢弃**：`attach_permission_notifier` 找不到 owner
  连接时改为立刻 `cancel_session(…, DISCONNECTED_REASON)`（对齐 question 模块「owner
  断连即 skip」的既有语义），run 不再等满超时。
- **Web 重连后不重新订阅当前会话**（`agentj-ui/apps/web/src/App.tsx`）：新增 effect
  （依赖 `[sharedClient, activeSessionId]`），在客户端（重）连通与切换会话时重新
  `session/subscribe`，重新接上仍在运行的 `$/progress` 输出流（对齐 TUI 既有行为）。
- **原始 `-32805` 错误码直达用户**（`agentj-ui/apps/web/src/RunPanel.tsx`）：新增
  `sessionBusyMessage()`，把 `SessionBusy` 呈现为「该会话已有任务在运行…」提示。
- **排空期间连接被提前释放会丢响应**（`crates/agentj-ipc/src/lib.rs`）：抽取出的
  `pump_requests` 一度按值接收 `conn`，函数一返回就析构 `TcpConnection`——tokio 的
  `OwnedWriteHalf` 析构时会 shutdown 写方向，于是「EOF 前已受理、响应尚未写完」的请求被
  对端看成 EOF（服务器侧写入得到 `BrokenPipe`），`serve --port` 下表现为紧随其后的 TCP
  连接收到空响应。现改为借用 `&mut Box<dyn Connection>`，让连接活过排空循环，恢复
  「在飞行的响应仍送达」的既有保证。
- **`login_limiter` 日志捕获用例偶发失败**（`crates/agentj-ipc/src/login_limiter.rs`）：
  两个捕获用例原先用 `tracing::subscriber::set_default`（线程本地）安装捕获订阅者，其
  set/drop 会重建全局 callsite interest 缓存，与同一测试二进制内并行运行的其它测试的日志
  互相竞争，偶发丢掉 `record_success` 的 `login ok` 事件（`--test-threads=8` 下 40 次
  复现 5 次）。现把捕获订阅者改为**进程级**默认（`OnceLock` + `set_global_default`，
  只装一次）并用互斥量串行化两个捕获用例；日志行可能与其他测试交错，但断言均为子串匹配
  ——同样 40 次压力复现 **0 次**。

### Tests

  `serve_connection_end_of_input_denies_pending_approval`（真实链路：`scripted_conn` +

## 0.29.5 —— `serve` / `dashboard` 不再强制预先配置密钥（修复）

`serve` / `dashboard` 的核心承诺是「客户端链接 Key 即生效」（0.29.0 设计 D2/D3/D7），
但启动装配阶段一旦解析不到任何密钥就**直接报错退出**，导致首次部署必须先跑一次
`agentj auth login` 才能起服务——与「在 Web/TUI 设置里链接」自相矛盾。现收窄 fatal 边界：
空的 provider 集合**不再一概失败**，只有**没有可录入凭据客户端**的命令仍启动即报错。
协议 wire 面**不变**（`PROTOCOL_VERSION` 仍 **0.18.0** / 28 方法 / 78 schemas）。

### Fixed

- **`agentj serve`（含 `dashboard`）无密钥时拒绝启动**：`crates/agentj-cli/src/providers.rs`
  的 `build_providers` 在集合为空时返回 `Err("no usable model provider…")`，
  `crates/agentj-cli/src/main.rs` 对除 `run --attach` 外的所有命令 `bail!`，
  `serve` 因此进不了「客户端录入密钥」这条路径。现 `build_providers` 只在 `warnings`
  里报告该文案（导出 `providers::NO_USABLE_PROVIDER` 常量作为唯一文案来源），
  由 `main` 决定其后果：
  - `serve` / `dashboard`：启动继续，逐个 provider 打印跳过警告 + 一条汇总警告；
    客户端「设置 · 订阅」链接 Key 后当场重建并替换 provider（免重启）。
  - `run`：仍然启动即报错退出非 0，避免无凭据的上游请求。

### Changed

- 单测 `crates/agentj-cli/src/providers.rs::no_usable_provider_is_a_hard_error` 改为
  `keyless_provider_set_is_reported_not_fatal`（断言 `Ok` + 空集合 + 汇总警告）。
- `crates/agentj-cli/tests/e2e_auth.rs` 的 keyless 用例改用 `run`（原用 `serve`——
  正是被测缺陷），并新增
  `crates/agentj-cli/tests/e2e_serve.rs::keyless_provider_set_still_boots_serve`
  守护「无密钥也能起服务、打印监听地址并保持常驻」。

## 0.29.4 —— opencode-go 订阅真实 key 端到端调测适配（修复）

以真实订阅 key 对 opencode-go 三条 wire 路由（`/v1/chat/completions` / `/v1/messages` /
`/v1/responses`）做端到端调测，暴露并修复 4 个缺陷；另修复一个使
`cargo test --workspace` **永不终止**的 e2e 挂起。协议 wire 面**不变**
（`PROTOCOL_VERSION` 仍 **0.18.0** / 28 方法 / 78 schemas）。

### Fixed

- **命名空间 model id 泄漏到上游 wire**（三条路由全中）：catalog 内部 id 带
  `opencode-go/` 前缀（路由查找用），但 `OpenCodeGoProvider::route()` 只返回 wire format，
  `options.model` 原样透传 → 网关收到 `opencode-go/space-bunny` 并回 `unknown model`。
  现经 `catalog_source::bare_id()` 去掉前缀后再发送。
- **`/v1/responses` 文本 delta 解析错形状**：解析器读 `json["delta"]["text"]`，真实 wire 是
  `{"type":"response.output_text.delta","delta":"<text>"}`（`delta` 是**字符串**）→ 所有
  responses 模型（`grok-4.7` / `gpt-6-luna` / `muse-spark-*`）**输出恒为空**。
- **`/v1/responses` 工具参数 delta 解析错形状**：解析器读 `json["delta"]["arguments"]`，真实
  wire 是 `{"type":"response.function_call_arguments.delta","delta":"{\"pattern\":\"*.rs\"}"}`
  → 工具调用参数恒为空。两处均改为「字符串优先、旧对象形状容忍」解析。
- **`temperature` 不被支持导致 400**：`claude-haiku-5-5`（messages）与 `gpt-6-luna`
  （responses）拒绝该参数（`400 ... temperature is deprecated / unsupported`）。新增
  `agentj_model::retry::send()`：判定为「仅 temperature 不支持」时去掉该字段**重试一次**，
  其余错误仍按 `gateway_error::api_error` 上抛；三个 transport 各自私有的 `api_error`
  收敛到 `gateway_error`，并顺带在同一入口补齐 `429` → `RateLimited`（含 `Retry-After`）映射。
- **`e2e_permission` 无限挂起（`cargo test --workspace` 不终止）**：该用例把 `session_id`
  硬编码为 `"s1"`，而 `session/new` 返回真实 UUID → `session/run` 回
  `session error: session 's1' is inactive`，随后裸 `read_line` 在没有匹配回复时**永久阻塞**。
  现从 `session/new` 回复取真实 id，且所有读取改为带 20s 截止的通道接收（超时即失败而非挂起）。

### Changed

- **`[permission] timeout_ms`**：`ask` 审批的自动拒绝等待预算可配置（省略 = 60s 设计默认）；
  `e2e_permission` fixture 设为 **800ms**，该用例从「无限挂起」变为 **0.85s** 完成。

## 0.29.2 —— opencode-go 路由改为 API 派生（修复）

opencode-go 的 `format`（三线端点路由）原来自仓库提交件 `models/opencode-go.json`，而该表由
`gen_opencode_catalog` 里一份**手写的 20 条 id → format 种子**维持。核对结论：`GET
/zen/go/v1/models` 只回 id（45 条，字段仅 `id/object/created/owned_by`），不含端点元数据；而
models.dev（`https://models.dev/api.json`）的 `opencode-go.models.<id>.provider.npm` 与官方
[端点表](https://opencode.ai/docs/go/#api-endpoints)「AI SDK 包」一列逐条对应（12/12 非 chat
模型零冲突，20 条 chat 模型经 provider 级默认继承吻合）——即端点路由完全可由公开 API 派生。

### Fixed

## 0.29.0 —— Web/TUI 链接 opencode-go API Key（功能）

订阅二期（v0.27.x）给了设备码登录与账号级目录，但「链接 API Key」这条官方路径（用户从
opencode.ai 控制台复制 key 粘贴进 AgentJ）此前只能靠手写 `auth.json` 或环境变量，而且
「链接后是否真的在跑」要等重启内核。本版本把 API Key 链接做成两端一等能力：一次调用
完成**校验 + 落盘 + 运行期激活 + 账号目录回传**，Web 与 TUI 都能输入、看到三态（已校验 /
未校验 / 已拒绝）并随时解除链接。全部 wire 变更为**加性**，此前客户端零破坏。

### Added

- **IPC 方法 `auth/setApiKey` / `auth/clearCredential`**（`@since 0.18.0`，契约见协议规范
  §8.28 / §8.29）：一次 `GET {console}/api/v2/config` 同时完成校验与目录，结果三态——
  `verified`（落盘 + 激活 + `source:"account"` + 播种 60s 模型缓存）、`unverified`（超时 /
  网络不可达 / 5xx / 畸形响应：**仍然落盘**并标注未校验，目录退到 live ∩ overlay，绝不
  编造）、`rejected`（401 / 403：**不落盘、不注册**，`error.kind` ∈ `unauthorized` /
  `entitlement`，文案内核自产、不回显上游正文）；参数非法（空 key / 未知 provider /
  非 opencode-go）仍走 `-32602` + `error.data.reason`（`invalid_params` /
  `unknown_provider` / `unsupported_provider`）。`auth/clearCredential` 移除凭据，并按
  剩余凭据收敛注册（仍有 env key → 重建；无 key → 注销），无条目时返回
  `cleared:false` 的成功响应。
- **运行期激活（无需重启内核）**：链接成功立刻重建并**替换注册** opencode-go provider，
  同时失效该 provider 的模型 / 用量缓存；设备码登录 `auth/devicePoll` 的 `authorized`
  分支复用同一激活路径（顺带修掉「Web 登录后仍要重启才能跑」的既有缺口）。
- **内置 opencode-go provider 条目**：用户 config 未声明 `kind = "opencode-go"` 时自动追加
  `base_url = "https://opencode.ai/zen/go"`、无 `api_key_env` 的内置条目（显式配置优先、
  不写用户 TOML）；无凭据时跳过并附「可在设置 · 订阅中链接 API Key」指引。
- **Web 设置 · 订阅新增「链接方式」区块**：`type="password"` + `autoComplete="off"` 的遮蔽
  输入、链接 / 解除链接按钮、三态回显、「将替换现有 OAuth 凭据」提示、
  `effective_source=env` 时显式提示「环境变量当前优先」；不写 `localStorage`、提交后清空
  输入框；设备码登录保留为次选。
- **TUI 订阅 overlay 新增链接模式**：`i` 进入输入、`Enter` 提交、`Esc` 取消，输入只渲染
  遮罩字符（帧内不出现明文），同样回显三态与 env 优先提示，并说明凭据写入
  **所连接内核所在的机器**。
- **文档与绑定**：协议规范补 §8.28 / §8.29 与 §3.4 / §9.1 / §10 / §11.3 的 0.18.0 条目；
  订阅指南按新路径重写；`@agentj/protocol` 类型与 `@agentj/sdk` `METHODS` 重新生成
  （28 条）。

### Changed

- **opencode-go 的 composer 模型列表改由账号目录驱动**：Web 链接成功（或
  `model/list {refresh:true}`）返回的目录作为**覆盖层**按 provider 替换条目（不追加重复
  项），用户未显式选择时自动选中首个账号条目；`kernel/status` 仍作连接期初值，该选择
  只作用于当前会话的 per-run 覆盖（**不改 `config.toml`**）。
- **协议版本 `0.17.0` → `0.18.0`**、方法面 26 → 28、schema 72 → 78；工作区
  `0.28.0 → 0.29.0`。`kernel/status` 与既有方法 / 字段的语义逐字不变。

### 已知边界（未做）

- **链接期间的时序**：替换 / 注销注册与并发 `session/run` 之间没有全局互斥——**进行中的
  那一轮 run 可能仍使用旧凭据，新凭据从下一轮生效**。
- **写入目标**：凭据写入**当前连接内核所在机器**的 `auth.json`；`--attach` / 远程 `serve`
  场景下即远端主机，非回环 `serve --host` 必须配 `--token`（既有要求，文档重述）。
- **不泄露**：结果只经 `redact()` 暴露 `key_hint`，完整 key 不出现在结果 / 日志 / 错误文案 /
  前端持久化中；两个方法**不新增权限门**（与既有 `session/run` 同级）。
- 不做多账号 / 账号切换（同一 provider 重复链接 = 替换）；不做 OS keyring。
